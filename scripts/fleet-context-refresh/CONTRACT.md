## Native admission and dispatch

An actual current Operator-owned `python3 controller.py tick` can prepare admitted work and perform guarded reserve/handover when the explicit activation flags permit it. External callers can observe and stage but cannot impersonate actors. The actual current Operator starts the deterministic duty with `python3 controller.py schedule --until UNIX_SECONDS`. The mandatory end time is finite and in the future. The scheduler inherits that shell's real environment, verifies native Operator identity/generation before every tick, and stops on retirement, end time, disabled activation policy, controller lock contention or an uncaught tick refusal. It never synthesizes actor identity or copies a Root token. Its interval is the shortest configured seat poll interval; each seat's idle observation still enforces its own interval. The controller lock is released during waits so worker checkpoint/acknowledgment can proceed. A separate nonblocking scheduler lock prevents duplicate duties. An in-flight guarded tick completes at its safe boundary before the end-time stop; no new tick starts after the deadline.

`scheduler-summary.json` stores only fixed aggregate phase counts, iteration count and timestamps; it contains no arbitrary native exception output, credentials or actor environment. The summary and lock files are excluded from publishing. Pending ambiguity markers remain authoritative across scheduled ticks. Existing task receipt reuse requires the exact current producer generation. Scheduling/activation remains a separate deployment step; no scheduler was started by this implementation.

For an enrolled worker, `publish_task` uses supported `rig coordinator admit` for an exact body/input/resource/return contract. It then creates a durable coordination task addressed to the enrolled current coordinator; it does not assign worker work as Operator. For rigs with an existing coordination plan, the Operator appends the exact refresh task and distinct recovery inspection through authenticated native `POST /api/coordinator/coordination-plan`. Existing stable task fields are retained; only explicitly supplied admissions refresh. Recovery task expiry authorizes inspection and reporting, never reset/retry of a started attempt. The current genuine coordinator runs `coordinator-dispatch --route PATH`; the controller verifies owner/generation/active lease and an actual in-progress current canonical baton. It uses native `coordination-reconcile` for planned work, retaining native qitem identity and supported system provenance, so current admission/activity/custody checks stay authoritative. For legacy enrolled rigs without a plan, it freezes the saved epoch envelope and executes supported `rig queue create --dispatch-file`. The daemon still validates baton/custody, package bytes and resource admission. A recovery/expired roster yields a concrete hold. No raw send helper exists in this candidate.

The worker claims the real admitted task. After its terminal closure it runs `worker-disposition --route PATH --evidence OWN_ARTIFACT` from that same generation. This creates the exact durable return JSON and invokes native `rig coordinator dispose`; the controller verifies the persisted disposition. For preparation, this must happen before authoring the final checkpoint, so native custody/resources are reconciled. Disposition is not rotation acceptance. Successor acknowledgment, validator-authored attestation, exact current task claims and Operator release remain separate gates.

Unenrolled legacy destinations retain native transport-authored queue creation. Registered coordinators and Kernel coordination destinations use the daemon's supported coordination traffic path. None of these paths enables enrollment or rewrites a coordination plan.
