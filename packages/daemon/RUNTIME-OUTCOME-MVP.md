# Shared runtime outcome MVP

The common coordinator `dispose` domain boundary persists an exact generation-attributed terminal outcome job. The same boundary applies to Codex, Pi and other harnesses; there is no rig-name switch. Genuine current Kernel Operator uses `POST /api/coordinator/outcome-configure` (the existing managed transport authentication) to install a revision with `rigId`, `operatorGeneration`, `mode`, `dataClass`, strict `allowPaid`, optional strict `allowUnqualifiedNegativeAdvice`, reviewed adapterConfig and dated exact-config qualification reference. Configuration is per enrolled rig and requires its existing admitted coordination plan. Unconfigured rigs remain off. Rollout must explicitly inventory and configure each enrolled project's policy; installation alone does not enforce all projects.

In enforce mode a pending assessment gates exact return acceptance until consumed. Qualified binary advice, or explicitly opted-in structurally validated **unqualified negative advice**, can request validation/recovery. Unqualified coverage remains unknown; no calibration or completeness is invented. The rubric asks only whether the return explicitly says required work remains unfinished. A `no` answer is not acceptance. Current holder must still make an attributed technical acceptance against the original native return/evidence. Invalid/unavailable/truncated results use existing deterministic successful-return acceptance rules; failed actual states still require recovery. Protected boundaries, independent review, exact package admissions and current capacity remain unchanged.

Negative advice creates only the previously admitted distinct recovery task through ordinary coordinator reconciliation. Its actual queue pickup establishes execution. If no recovery task exists, an exact disposition/policy/generation-bound, deduplicated Kernel Operator notice provides the missing-plan action, deadline and holder return path; acceptance stays gated. Unresolved enforcement cannot be erased by changing policy revision. A successfully returned and explicitly holder-accepted recovery permits explicit parent acceptance. Historical markers match only the current exact disposition/revision.

The durable consumer is per-rig single-flight and uses SQLite compare-and-swap across processes. A crash-stale running job falls back after 15 seconds without another external request. Provider timeouts are capped at 3 seconds. Input, worker generation/configuration, policy qualification and coordinator epoch/generation are checked before and after inference. Changed input suppresses advice/effects. The common HTTP dispose route drains immediately; registered current-Operator coordinator-continuity watchdog drains after authenticating its job/plan. No new watchdog is automatically installed. Native transport provenance is never replaced by forged headers.

Privacy/paid/hosting/credential enforcement comes from the unchanged reviewed six-module adapter (manifest 3162440ba995dee6e90799523142d6c9f657c8ded6052faeb95e7b3c160051f5). Exact assignment and attributed structured return text are the input; no artifact dereference, raw session transcript export or credential read is added. Hosted private routing and paid access require explicit provider contract opt-ins. Receipts retain actual model/provider/rubric/coverage/calibration provenance and distinguish negative unqualified advice, suppression and fallback. No receipt grants authority.

Limitations: this slice assesses coordinator-enrolled terminal returns, not arbitrary chat turns or every historical outbox event. It does not validate report contents, qualify models from a label, install production policy, enable production rotation, or resolve owner access. Real live provider fixtures are diagnostic rather than calibration. The adjacent sustained pending-assignment re-wake gap is a separately reviewed source repair.
