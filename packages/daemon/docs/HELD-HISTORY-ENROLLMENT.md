# Explicit contained-history adoption

Default enable and legacy inventory retain zero-uncertainty refusal. This opt-in path does not declare UNKNOWN history delivered, obsolete, or completed.

1. Current Operator requests `POST /api/coordinator/legacy-inventory` with `{rigId, authorizationId, adoptHeldHistory:true}`. Only exact server-HELD rows backed by the quarantine operation qualify; other unresolved effects remain blocking.
2. Actual current Lead creates a finite transport-attributed task to the current Operator. Operator must actually claim it. Its exact body is `{kind:"coordinator-held-history-recovery.v1", rigId, operationId, owner, generation, lead, leadGeneration, effects:[exact adopted IDs], action:"reconcile-preserved-unknown-history", deadline, returnPath:{session:lead, queueId}}`. Queue expiry is finite, future and no later than the deadline; deadline is at most twenty minutes ahead. The task supplies accountable recovery and its concrete return path, not permission to withdraw history.
3. Refresh exact inventory and use existing Lead-authorized `migrate-legacy`, additionally binding `heldHistoryRecovery:{queueId,rowHash}` (canonical full current queue-row digest). Existing obligations, resource exclusivity, current claims, generation and independent admissions remain mandatory. Migration atomically appends original and imported custody hashes and preserves all original transport rows. It does not ACK the coordinator or grant qualification.
4. Existing reconciliation/ACK and admitted product dispatch continue. Durable SQL guards prevent historical replay, unhold, payload rewrite or receipt replacement; supported separately authorized retirement remains possible in its existing transaction order.

An expired, terminal, changed or retired-owner recovery binding refuses automatic takeover with `coordinator_held_history_recovery_required`. Independent ordinary product dispatch is unaffected. Accountability can be renewed without rewriting old adoption receipts:

`POST /api/coordinator/held-history-recovery-bind`, authenticated as the actual current Operator, body `{rigId, operationId, effects:[exact current HeldHistoryRef objects from opt-in inventory], recovery:{queueId,rowHash}}`. The replacement task must be authored by the current actual coordinator holder and actually claimed by Operator, with the body above binding this new operation. All unresolved adopted IDs must be included. The append-only operation receipt becomes the current binding. Same-operation replay rechecks live task/generation/expiry; expired or terminal replay cannot restore accountability. Original task receipts and adopted history remain unchanged.

Limits: source/workflow tests qualify this contract only. No production enrollment, historical disposition, native pilot, provider permission or broad project qualification is established here. Original quarantine expiry does not silently unhold retained debt. Additional executable uncertainty still blocks takeover/import. A recovery task becoming terminal before debt resolution requires a newly claimed finite replacement; it is never silently considered completion.

## Unavailable issuer recovery

If the old finite history-recovery task expires while its actual Lead is natively unavailable, the existing explicitly Operator-registered `coordinator-continuity` supervisor can mint a replacement notice. It does so only after the real unavailable-owner transfer reaches the adopted-history accountability refusal. The notice carries exhaustive exact held references and the current job, plan revision, epoch, owner/Operator generations, plus a finite queue expiry/deadline (at most twenty minutes). A matching append-only server operation binds its exact body and creation attribution. Mere expiry, unknown native activity or role labels cannot mint this admission.

The same authenticated `held-history-recovery-bind` operation can consume this particular notice after the genuine current Operator actually claims it. Bind and replay recheck fresh generation-bound native absence, current explicitly opted-in plan/job, finite task admissions, eligible Peer, exact current held references, server provenance and task expiry/claim. The absent Lead is never impersonated. Changed authority, returned owner, expired plan/task, unclaimed/retired Operator or forged/mismatched notice refuses. Ordinary current-Lead-authored renewal is unchanged. Successful renewal supplies finite accountable custody; it does not itself transfer authority, waive ACK, dispose history or grant product admission. A later real supervisor pass performs the existing guarded transfer and genuine Peer claim/ACK.
