# Finite wake-control deadline recovery

Wake-ladder refusal notices persist the requested60-second deadline in the supported queue creation `expiresAt` metadata and the body. The waiting view exposes it as `wake-ladder:control-deadline`; it is an accountability deadline, never queue expiry, implicit completion or permission to alter protected work. Legacy ada body-only deadlines are also scanned.

The existing ladder scheduler scans at most60seconds apart. Ordinary rung attempts retain their existing retry due gates. A60-second deadline may therefore be acted on by the next scan up to60seconds later, plus actual execution duration. This is bounded automatic action, not a60-second native pickup SLA. Restart preserves the database deadline and scan behavior; no extra timer engine is introduced.

Only unclaimed pending typed watchdog→Kernel Operator original notices are scanned. After the deadline, unchanged exact protected source facts and asserted actual current Operator generation permit one atomic correlated recovery notice/intent, with its own finite requested response deadline and exact claim/return path. The correlation is parent/current Operator generation, validated against any existing row. Returned commitments precede transport, so later failure cannot omit a durable child. The old indeterminate intent is never re-driven, no product task is duplicated, and the original control/source/claims/resources are not rewritten.

Correlated recovery notices are not themselves parents: no recursive or unbounded self-escalation. Repeated scans reuse the same correlated notice regardless of its open/returned state, emit no new send, and keep `wake_control_deadline_missed` failed/visible while the original remains unclaimed. That failed status is the finite exhausted backstop, not progress or an inferred current Peer. A missed correlated response deadline does not mint grandchildren; the visible original/current recovery custody requires genuine Operator action under the same supported owner/return contract. Any Peer failover uses existing qualified/current authority controls separately.

Actual claimed/in-progress/blocked originals remain their owner's custody and are excluded. Their explicit supported blocked wake timers remain intact. Terminal protected source facts produce only a source-terminal receipt, never automatic acceptance/control closure. Changed facts, unknown/current-Operator loss, correlation conflict or commit/delivery failure report an exact refusal instead of synthesizing authority. A genuine Operator's later claim/block/return is actual pickup evidence; an automatic wake attempt or generated notice is not.

Tests use real SQLite reservation/admission/queue/transport seams. Source verification grants no pilot or production authority; runtime adoption and genuine automatic pickup require independent review and the sole live custodian's fresh bounded proof.
