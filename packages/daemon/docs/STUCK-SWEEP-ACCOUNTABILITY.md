# Refused stuck-finding scope

The standing sweep scans the instance. A candidate or existing finding whose supported queue write is refused no longer prevents other candidates/rigs or later resolution from running. Dispatch admission is unchanged: a detector never supplies a coordinator token or mints a product package to impersonate the old obligation creator.

`runStuckSweep` returns failed with exact per-scope `refusals` plus the actual already committed `findings`. Health retains failed and identifies the first refused queue/code; `findingsRouted` counts committed new finding/control rows only, excluding refresh and closure. A failed tick is not an all-project healthy verdict, and zero routed rows is not proof that earlier unrelated runtime operations made no writes.

A refusal stages a distinct `watchdog@system` → actual current `operator-agent@kernel` control notice using the existing internal Operator-generation assertion, queue transaction, and generation-tagged wake intent. It names the original ID/source/destination/body/fact hashes, guard, intended route, action, finite deadline, and exact supported completion/failure queue path. This is no assignment/admission/resource reservation and never replaces the original source identity. Notice commit/wake is not pickup or original completion. Without a current Operator or on source drift, the result retains the explicit recovery error while independent work continues.

Same open facts/reason/current-generation deduplicate; closed notice or changed facts/generation creates a new notice preserving old receipts. Old-generation wakes remain pending/refused by existing delivery freshness checks. Only actual Operator custody and supported queue return completes a control notice; changed/terminal original source does not auto-complete claimed Operator work. Operator must reread current source/effect custody and use the existing admitted reconciliation/disposition path, or block the exact notice with reason, next action and deadline. Unknown historical effects/claims/body/resources stay unchanged; no blanket retirement, replay, unarchive, fake qualification, native restart or raw SQL repair is authorized by this notice.

Source fixtures exercise first enabled unadmitted diagnostic refusal, actual earlier commits and later independent progress/resolution, current Operator pickup, recovery dedup/closure/source/gen changes, unavailable Operator and late-generation delivery. Fixture SQL is confined to in-memory test databases and is not live corruption evidence.
